> (Tag の書式と生成、Tag と Group の文字数の上限、Tag の重複の回避、マシン ID)

## 1. 概要

### 1.1 目的

予約を一意に識別する Tag について、書式、生成方法、重複回避の規則を定める。
あわせて、次の 3 点を定める。

- Tag の一部であるマシン ID の生成と保存
- Tag と Group の文字数の上限
- 予約件数の上限に達した場合の扱い

### 1.2 範囲

Tag の生成と一意性に関する、振る舞いの規則と分類の意味を定める。
実装の詳細は対象外とする。

---

## 2. 設計方針

### 2.1 分類方針

- Tag は、登録時刻・マシン ID・乱数の 3 つの入力だけで決まる固定長の文字列とする。
  生成の処理は時計と乱数を使わず、同じ入力からは同じ Tag を返す。
- Tag は (batchId, alarmId) から再計算できない。Tag を引く手段は対応表であり、この仕様では扱わない。
- 一意性は 2 段で守る。乱数の幅 (64 bit) で確率的に確保し、予約の追加の前に予約一覧と対応表で確認して構造的に確保する。
- 失敗は黙って補わない。不正な入力と保存領域の異常は、既定値で埋めずエラーとして返す。

### 2.2 設計上の前提

- Tag と Group の文字数の上限は、公式ドキュメントの値 (64 文字) を前提とする。
  この値は ToastNotification の記述であり、予約通知 (ScheduledToastNotification) での値は **未測定**。
- 文字数は UTF-16 code unit 数で数える。Tag は ASCII だけで構成するため、文字の個数と一致する。
- 登録時刻 (ローカル日時)、マシン ID、乱数は呼び出し側が与える。時計と乱数の取得元は、差し替えられる入力点とする。
- 予約件数の上限は、公式ドキュメントでは 4096 件。実機での値と適用範囲は **未測定**。
- CLI のプロセスは一度に 1 つだけ動かす。並行して起動した場合は対象外とする。

### 2.3 外部設計の概要

> **根拠**: 外部設計の対話 (Phase E) と、利用者が確認した設計方針 (Phase D) に基づく。

#### 機能の分割

| Unit             | Responsibility                                                                   | REQ Coverage |
| ---------------- | -------------------------------------------------------------------------------- | ------------ |
| Tag 生成         | 登録時刻・マシン ID・乱数から、決められた書式の Tag を組み立てる (純粋)          | REQ-F-016    |
| 重複回避         | 生成した Tag が予約一覧の Group=kallr か対応表に既にあれば、乱数部分を再生成する | REQ-F-017    |
| 長さ・件数の維持 | Tag を文字数の上限以下に保ち、上限の件数まで重複なく登録できる状態を保つ         | REQ-F-007    |
| マシン ID の保持 | マシン ID を初回に生成して保存し、以降は同じ値を返す                             | REQ-F-019    |

#### 構成要素の関係

```text
+------------------+     +------------------+
|  マシン ID の保持 | --> |     Tag 生成     |
+------------------+     +------------------+
                              ^        |
+------------------+          |        v
| 時計 / 乱数の     | --------+   +------------------+
| 取得元 (注入)     |             |    重複回避      |
+------------------+             +------------------+
                                       |
                                       v
                [予約一覧 Group=kallr と対応表の Tag を参照]
                                       |
                                       v
                          Tag を予約の追加へ渡す (別 spec)
```

重複回避は Tag 生成を繰り返し呼ぶ。マシン ID の保持は、Tag 生成より先に値を用意する。
この順序のほかに、このファイルの範囲内で追加の順序制約はない。

#### データの流れ

```text
[登録時刻] --+
[マシン ID] -+--> [Tag 生成] --> [重複確認] --> [Tag]
[乱数] ------+                       |
                                     v
                          [乱数の再生成 (最大 3 回)]
                                     |
                                     v
                          (3 回で解消しない場合) --> [エラー]
```

### 2.4 対象外

> **根拠**: 以下はすべて REQUIREMENTS の「Out of Scope」に基づく。

- Windows 以外の OS の Tag の扱い ← REQ: Out of Scope #1
- ハッシュによる Tag の短縮 (既存の短縮処理の採用)。本検証では Tag を短縮しない ← REQ: Out of Scope #6

### 2.7 DD を DR に昇格する基準

> **目的**: DD を正式な DR に昇格するかどうかを判断するための指針。昇格は人が判断し、自動では行わない。

**昇格を検討する場合:**

1. 複数の仕様またはモジュールに影響する
2. 将来の設計の選択肢を縛る
3. 実際に複数の選択肢があった
4. 外部の関係者によるレビューが必要

**DD のまま残す場合:**

- この仕様の中だけで完結する
- 大きな代替案がなかった
- 根拠が文脈から明らかである

> **Action**: 昇格するときは `/deckrd dr --add` を実行し、DD の Status を `Promoted → DR-xx` に更新する。

## 3. 振る舞いの仕様

### 3.1 入力

- 入力の種類:
  - Tag 生成: 登録時刻 (ローカル日時)、マシン ID、乱数
  - 重複回避: 生成した Tag と、予約一覧 (Group=kallr) の Tag の集合、対応表の Tag の集合
  - マシン ID の保持: 保存済みのマシン ID。保存領域が存在しないとき、または存在して ID がないときは未保存
- 前提:
  - 登録時刻は、年が 0000〜9999 のローカル日時
  - マシン ID は小文字 16 進 8 桁 (32 bit)
  - 乱数は小文字 16 進 16 桁 (64 bit)
  - 乱数は暗号論的乱数から得る (REQ-F-016 の Rationale)

<!-- impl-note: Tag 生成は
  generateTag({required DateTime registeredAt, required String machineId, required String random}) -> String。
  純粋関数で、不正入力は ArgumentError -->
<!-- impl-note: 時計は abstract interface class ClockProvider { DateTime now(); }、
  乱数は abstract interface class RandomSourceProvider { String randomHex64(); } -->
<!-- impl-note: マシン ID は abstract interface class MachineIdProvider { String machineId(); }。
  保存は SQLite (package:sqlite3)、書き込みはトランザクション -->

### 3.2 出力と終了コード

- 出力の意味:
  - Tag 生成: 予約を識別する 40 文字の文字列
  - 重複回避: 予約一覧の Group=kallr と対応表のどちらにも存在しない Tag、またはエラー
  - マシン ID の保持: マシンごとに固定の 8 桁の 16 進文字列
- 取りうる結果:
  - 日時部分 14 桁・区切り・マシン ID 8 桁・区切り・乱数 16 桁の順に並ぶ Tag。小文字 16 進と数字だけで構成する
  - 不正な入力によるエラー (Tag を返さない)
  - 再生成の上限を超えたことによるエラー (予約を作成しない)
  - 保存領域が存在するのに読めない、または壊れていることによるエラー (終了コード 2。マシン ID を返さない)

## 4. 判定規則

<!--
Rule ID format: R-NNN (sequential, stable)
規則 ID は「要件との対応」と「例外的なケース」から参照する。
-->

評価の順序は、動作ごとの小節の中で固定する。add の流れでは、4.3 → 4.1 → 4.2 の順に適用する。

### 4.1 Tag の生成

Evaluation MUST follow this order:

| Rule ID   | Step | Condition                                                                                                     | Outcome                                                                                                                                                                                 |
| --------- | ---: | ------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TAG-R-001 |    1 | 登録時刻の年が 0000〜9999 の範囲外、マシン ID が小文字 16 進 8 桁でない、または乱数が小文字 16 進 16 桁でない | エラーにする。値を補正したり既定値で補ったりしない。Tag を返さない                                                                                                                      |
| TAG-R-002 |    2 | TAG-R-001 に該当しない                                                                                        | 登録時刻の「年 4 桁・月・日・時・分・秒 各 2 桁」を、ゼロ埋めの 14 桁にする。秒未満は切り捨てる。続けて区切りの `-`、マシン ID、区切りの `-`、乱数をこの順に並べた 40 文字を Tag とする |
| TAG-R-003 |    3 | 同じ入力が再び与えられる                                                                                      | TAG-R-002 と同じ Tag を返す。時計・乱数・保存領域を参照しない                                                                                                                           |

規則の順序は変更しない。

### 4.2 Tag の長さと重複の回避

Evaluation MUST follow this order:

| Rule ID   | Step | Condition                                                                                            | Outcome                                                                                                                              |
| --------- | ---: | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| TAG-R-004 |    1 | Tag を生成する                                                                                       | Tag は常に 40 文字。Group は `kallr` の固定値 (5 文字)。どちらも文書上の上限 64 文字以下を保つ。実機での上限は未測定 (未解決事項 #1) |
| TAG-R-005 |    2 | 生成した Tag が、予約一覧の Group=kallr、または対応表の Tag に存在するかを、予約の追加の前に確認する | どちらにも存在しなければ、その Tag を予約の追加に使う                                                                                |
| TAG-R-006 |    3 | TAG-R-005 で存在する                                                                                 | 登録時刻とマシン ID は変えず、乱数だけを新しく取得して Tag を生成し直し、TAG-R-005 に戻る。再生成は初回の生成を除いて最大 3 回       |
| TAG-R-007 |    4 | 3 回目の再生成で得た Tag も存在する                                                                  | エラーで終了する (終了コード 2)。その Tag での予約は作成しない                                                                       |

規則の順序は変更しない。

### 4.3 マシン ID の生成と保存

Evaluation MUST follow this order:

| Rule ID   | Step | Condition                                                                   | Outcome                                                                                                |
| --------- | ---: | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| TAG-R-010 |    1 | 保存領域が存在するのに読めない、または保存済みの値が小文字 16 進 8 桁でない | エラーにする (終了コード 2)。新しい値を黙って作り直さない。マシン ID を返さない                        |
| TAG-R-008 |    2 | 保存済みのマシン ID がある                                                  | その値を返す。以降の起動でも変わらない                                                                 |
| TAG-R-009 |    3 | 保存領域が存在しない (初回の起動)、または保存領域は正常でマシン ID が未保存 | 32 bit の暗号論的乱数を小文字 16 進 8 桁にし、保存してから返す。保存に失敗したら値を返さずエラーにする |

規則の順序は変更しない。

> 規則 ID は採番順を保つ。このため、評価は TAG-R-010 が TAG-R-008 より先になる。

## 5. 例外的なケース

| Input                                                 | Classification                                                                           | REQ            | Rationale                                                                           |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------- | -------------- | ----------------------------------------------------------------------------------- |
| 登録時刻に秒未満 (ミリ秒など) がある                  | 切り捨てて秒精度の Tag にする (TAG-R-002)                                                | REQ-F-016      | 書式は 14 桁固定。秒未満の違いは乱数部分で区別する                                  |
| 年が 0000〜9999 の範囲外                              | エラー (TAG-R-001)                                                                       | REQ-F-016      | 日時部分を 14 桁に収められない。fail-first                                          |
| マシン ID の桁数が違う、大文字、16 進以外の文字を含む | エラー (TAG-R-001)                                                                       | REQ-F-016      | 書式を固定し、40 文字を保証するため                                                 |
| 乱数の桁数が違う、大文字、16 進以外の文字を含む       | エラー (TAG-R-001)                                                                       | REQ-F-016      | 同上                                                                                |
| 夏時間の切り替えで、同じローカルの秒が 2 回現れる     | Tag は生成できる。日時部分が同じになり得る                                               | REQ-F-016, 017 | 区別は乱数部分と重複確認 (TAG-R-005) が担う                                         |
| 夏時間の切り替えやタイムゾーンの変更をまたぐ          | 文字列順と登録時刻順が一致しない場合がある                                               | REQ-F-016      | 日時部分はローカル日時のため (DR-04)。順序の一致は通常の場合だけ                    |
| 生成した Tag が予約一覧に既にある                     | 乱数だけを再生成して TAG-R-005 に戻る (TAG-R-006)                                        | REQ-F-017      | 同じ Tag での追加を防ぐ                                                             |
| 生成した Tag が対応表にだけある (発火済み)            | 乱数だけを再生成して TAG-R-005 に戻る (TAG-R-006)                                        | REQ-F-017      | 予約一覧と対応表の両方を確認するため (TAG-DD-02)                                    |
| 3 回の再生成後も重複する                              | エラー (TAG-R-007)。予約を作成しない                                                     | REQ-F-017      | 上限を超えたら打ち切る                                                              |
| 置換のために Tag を生成する                           | 追加と同じ手順で新しい Tag を生成する (TAG-R-001〜TAG-R-007)                             | REQ-F-017      | 置換のたびに登録時刻と乱数から置換後の Tag を作る (REQ-F-005 の Rationale)          |
| Tag の実機での文字数の上限が 40 文字未満だった        | 未確認。測定後に書式を見直す (未解決事項 #1)                                             | REQ-F-007      | 公式ドキュメントの 64 文字は予約通知で未測定                                        |
| 予約件数の上限 N まで add で登録する                  | N 件すべて成功し、Group=kallr の Tag がすべて異なり、各 Tag が上限以下                   | REQ-F-007      | AC-009。実機での確認は手動検証                                                      |
| N+1 件目の登録が失敗する                              | 結果の記録のみ。合否に含めない                                                           | REQ-F-007      | REQ-F-007 の Rationale                                                              |
| 保存領域が存在するのに読めない、または壊れている      | エラー (終了コード 2)。作り直さない (TAG-R-010)                                          | REQ-F-019      | 別の値を黙って作ると、以降の Tag のマシン ID が変わってしまう                       |
| 2 回目の起動                                          | 保存済みの同じ値を使う (TAG-R-008)                                                       | REQ-F-019      | AC-011。再起動の前後で変えない                                                      |
| 保存領域が削除された後の起動                          | 初回の起動と区別できないため、新しいマシン ID を生成する (TAG-R-009)。この扱いは許容する | REQ-F-019      | マシン ID は Tag の一意性を足すだけで、一意性は乱数部分と重複確認が担う (TAG-DD-04) |
| 2 つのプロセスが同時に初めて起動する                  | 対象外 (一度に 1 つのプロセスだけを動かす)                                               | REQ-F-019      | 並行実行は対象外とする決定による                                                    |
