## PoC-W0 手順 1: .NET / C# コンソールから `AddToSchedule()` を呼ぶ

調査メモ: 6.1。Issue: #13。

### 環境

- Windows 11 Pro 10.0.22621
- .NET SDK 10.0.404 (`net10.0-windows10.0.19041.0`)
- コード: `poc/windows/w0-1-addtoschedule/` (ブランチ `chore-3/poc/windows-notification`)
- 形態: パッケージ化なし (MSIX ではない) の `W01.exe`

### 手順と結果

| # | 内容                                                                                                                          | 結果                                                                      |
| - | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 1 | AUMID `Kallr.Poc.W01` を指定して `AddToSchedule()` を呼ぶ (ショートカットなし)                                                | 例外なし。`GetScheduledToastNotifications()` に予約が出る。toast は未表示 |
| 2 | AUMID を持つスタートメニューのショートカットを作る (`register`)                                                               | 作成できた                                                                |
| 3 | 手順 2 の直後に予約した toast (1 分後)                                                                                        | 表示されなかった                                                          |
| 4 | 即時の toast (`Show`)                                                                                                         | 表示された。`notifier.Setting` は `Enabled`                               |
| 5 | 手順 4 の後に予約した toast (75 秒後)                                                                                         | 指定時刻に表示された                                                      |
| 6 | ショートカットを削除して予約した toast                                                                                        | 表示されなかった                                                          |
| 7 | ショートカットなし、レジストリ登録のみ (`HKCU\Software\Classes\AppUserModelId\Kallr.Poc.W01` に `DisplayName`) で即時の toast | 表示された                                                                |
| 8 | 手順 7 の状態で予約した toast (60 秒後)                                                                                       | 指定時刻に表示された                                                      |

- 予約の作成後、`add` のプロセスはすぐに終了している。toast は、そのプロセスが存在しない状態で表示された (W2 の予備的な所見。W2 としての合否はまだ判定しない)

### 制約と気付き

- `AddToSchedule()` は、デスクトップのコンソールアプリ (パッケージ化なし) から呼べた。調査メモ 6.1 で『記載なし』だった点は、この環境では使えるという結果になった
- 予約の呼び出しは、AUMID が OS に登録されていなくても成功し、一覧にも出る。表示されるかどうかは別
- 手順 1 では、ショートカットを作る前に予約したため表示されなかった
- 手順 3 は、ショートカットを作った約 1 分後で表示されなかった。手順 5 では表示された
  - 原因は未確定。ショートカットの作成直後は OS が AUMID を認識していなかった可能性がある。ほかの原因 (見逃し、集中モードなど) は切り分けていない
  - 再現して確かめるには、ショートカットを作り直した直後に予約し、表示までの待ち時間を測る
- 表示に必要だったもの: AUMID を持つスタートメニューのショートカット (W0-2 と W5 の入力)

### 調査メモで未確認とされた事項

| 事項                                              | 実機の結果                                                                                                                                                                               |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| デスクトップアプリで `AddToSchedule()` が使えるか | 使えた (パッケージ化なし、ショートカットあり)                                                                                                                                            |
| AUMID とスタートメニューのショートカットの要件    | AUMID の登録が必要 (手順 1、6 では表示されず、手順 5、8 では表示された)。登録の方法は、ショートカットまたは HKCU のレジストリキーのどちらでもよい (手順 8)。ショートカットは必須ではない |

### 設計への影響

- W0 手順 1 は合格。Task Scheduler 方式 (代替) には進まない
- 手順 2 (MSIX との比較) で、ショートカットなしでも表示される構成があるかを確かめる
- ショートカットの作成直後の挙動は、W5 (配布形式の制約) で再確認する
- レジストリ登録だけなら、管理者権限は要らない (HKCU への書き込み)。インストーラーなしで配る構成の候補になる
- 手順 7 の即時 toast について、登録前の状態 (何も登録していない) での即時 toast は確かめていない。手順 1 と 6 の予約 toast が出なかったことを、登録がない場合の基準にしている
- 登録の削除 (`unregister-reg`) と、ショートカットの削除後の挙動 (手順 6) は確認済み。PoC 後の後始末は、レジストリキーと `Kallr PoC W01.lnk` の削除

## PoC-W0 手順 2: MSIX と未パッケージの比較

調査メモ: 6.1。Issue: #16。手順 1 (#13) の結果が前提。

### 環境

- 手順 1 と同じ (Windows 11 Pro 10.0.22621、.NET SDK 10.0.404)
- MSIX 版: `poc/windows/w0-2-msix/` (`W02.exe`)。`build.ps1` で作成し、自己署名証明書 (`CN=KallrPoc`) で署名した
  - パッケージ名 `Kallr.Poc.W02`、PackageFamilyName `Kallr.Poc.W02_mvyfws2bdaesp`
  - 権限は `runFullTrust` のみ。コンソールから起動できるように実行エイリアス (`w02.exe`) を付けた
  - 通知用の AUMID はコードで指定せず、パッケージの AUMID を使う (`CreateToastNotifier()`)
- 未パッケージ版: 手順 1 の `W01.exe` をそのまま使った。実行前に、レジストリキーとショートカットが残っていないことを確認した

### MSIX 版の結果

| #  | 内容                                                          | 結果                                        |
| -- | ------------------------------------------------------------- | ------------------------------------------- |
| M1 | `identity` でパッケージ化された状態で動いていることを確認する | `family=Kallr.Poc.W02_mvyfws2bdaesp` と出た |
| M2 | 即時の toast (`show`)                                         | 表示された。`setting=Enabled`               |
| M3 | 約 20 秒後の toast を予約 (`add`)                             | 指定時刻に表示された                        |

- ショートカットとレジストリ登録は、どちらも手動では作っていない
- 予約の作成後、`add` のプロセスはすぐに終了している。toast は、そのプロセスが存在しない状態で表示された

### 未パッケージ版の結果 (W01.exe)

| #  | 内容                                                             | 結果                                                          |
| -- | ---------------------------------------------------------------- | ------------------------------------------------------------- |
| U1 | 何も登録せずに予約 (`add`)                                       | 呼び出しは成功。toast は表示されなかった                      |
| U2 | レジストリ登録後に即時の toast (`show`)                          | 表示された                                                    |
| U2 | レジストリ登録後に予約 (`add`)。登録は予約時刻まで削除しなかった | `list` に予約が出て、指定時刻に表示された                     |
| U3 | レジストリ登録を削除した後に即時の toast (`show`)                | `shown` と出たが、toast は表示されなかった。`setting=Enabled` |

- 過去の時刻を指定した予約は `ArgumentException (0x80070057)` になった。2 回起きたが、どちらも指定ミス (現在時刻より前) によるもので、パッケージの形態とは関係がない
- U1 の予約直後の `list` は空だった。実行した時刻が予約時刻を過ぎていたためとみられる (手順 1 では、`list` に予約が出ることを確認済み)
- U3 により、手順 1 で『未確認』とした『何も登録していない状態での即時 toast』は、表示されないことが確認できた

### 比較

| 項目                     | MSIX                                                                                      | 未パッケージ                                                         |
| ------------------------ | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `AddToSchedule()` の可否 | 使えた。予約 toast が表示された                                                           | 使えた (AUMID の登録があるとき)                                      |
| AUMID                    | パッケージの `PackageFamilyName!App` が自動で決まる。コードでは指定しない                 | コードで指定する。OS への登録が別に必要                              |
| ショートカット           | 不要 (作っていない)                                                                       | 不要。レジストリ登録だけで表示できる (手順 1、U2)                    |
| 登録しない場合           | 該当なし (インストールすると AUMID が付く)                                                | 予約の呼び出しは成功するが、toast は表示されない (U1、U3、手順 1、6) |
| 導入方法                 | 署名した MSIX のインストール                                                              | exe の配置と、HKCU のレジストリキーの作成                            |
| 権限                     | 自己署名証明書を `LocalMachine\TrustedPeople` に入れるために、管理者権限で実行した (注 1) | 不要 (HKCU への書き込み)                                             |
| 追加で必要な作業         | 署名証明書。本番では信頼される証明書 (入手方法は未調査)                                   | AUMID 登録の処理                                                     |

注 1: 管理者権限なしで同じ手順が失敗するかは確かめていない。Developer Mode で展開して登録する方法 (署名不要) も試していない。

### 調査メモで未確認とされた事項

| 事項                                              | 実機の結果                                                                                                                  |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| デスクトップアプリで `AddToSchedule()` が使えるか | MSIX・未パッケージのどちらでも使えた                                                                                        |
| AUMID の要件                                      | どちらの形態でも、OS が認識する AUMID が必要。MSIX はパッケージから自動で付き、未パッケージは HKCU のレジストリ登録で足りる |
| スタートメニューのショートカットの要件            | 必須ではない。MSIX もレジストリ登録だけの未パッケージも、ショートカットなしで表示された                                     |
| インストール方法・権限の要件                      | MSIX は署名とインストール (今回は管理者権限で実行)。未パッケージは管理者権限不要                                            |

### 設計への影響 (W5 への入力)

- 通知を出すだけなら、MSIX を使わなくてもよい。未パッケージ + HKCU のレジストリ登録で、管理者権限なしで足りる
- MSIX にすると、AUMID の登録処理は不要になる。代わりに署名証明書とインストーラー (MSIX のインストール) が要る
- どちらを採るかは、配布形式の要件 (W5) で決める。この PoC は、どちらでも `AddToSchedule()` が動くことまでを示した

### 未確認の事項

- MSIX のインストール直後に予約した toast が表示されるか (手順 1 では、ショートカットの作成直後に表示されなかった例がある)。今回は、インストールからの経過時間を測っていない
- 管理者権限なしでの MSIX のインストール (Developer Mode での登録を含む)
- MSIX のアンインストール後の予約済み toast の扱い
- 信頼される証明書での署名 (今回は自己署名のみ)

### 後始末

- MSIX: パッケージ `Kallr.Poc.W02` と、証明書 `CN=KallrPoc` (`LocalMachine\TrustedPeople` と `CurrentUser\My`) は削除済み
- 未パッケージ: レジストリキーは `unregister-reg` で削除済み

## PoC-W0 手順 3: Dart FFI から `AddToSchedule()` を呼ぶ

調査メモ: 6.1。Issue: #17。手順 1 (#13) の結果が前提。

### 環境

- Windows 11 Pro 10.0.22621
- Dart SDK 3.14.0 (`dart run` による実行。AOT コンパイルした exe は試していない)
- 依存は `package:ffi` のみ。WinRT のバインディング用パッケージは使っていない
- コード: `poc/windows/w0-3-dartffi/` (ブランチ `chore-17/poc/dart-ffi`)
- 形態: パッケージ化なしの `dart.exe` プロセス。AUMID は手順 1 と同じ `Kallr.Poc.W01`

### 実装方式

- `combase.dll` の `RoGetActivationFactory`・`RoActivateInstance`・`WindowsCreateString` などを `dart:ffi` で直接呼ぶ
- WinRT のインターフェースは、IID と vtable の位置を手で書いて呼ぶ。
  対象は `ToastNotificationManager`、`ToastNotifier`、`ScheduledToastNotification` ほか
- `win32` パッケージ 5.15.0 は `combase` と `IInspectable` までを持つが、トースト関連のインターフェースは含まない。そのため使わなかった (6.x は未確認)

### 手順と結果

手順 1 と同じ入力 (`--at`・`--title`・`--batch`・`--alarm`) で、同じ操作をした。

| # | 内容                                                                | 結果                                                                            |
| - | ------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 1 | `list` (予約なし)                                                   | 例外なし。出力は空                                                              |
| 2 | 約 3 分後の toast を `add` (group `B1`、tag `A1`)                   | 例外なし。Dart の `list` に予約が出た                                           |
| 3 | 手順 2 の予約を、手順 1 の C# 版 `W01.exe list` で確認する          | group・tag・時刻が一致した (Dart の予約を WinRT 側が同内容で認識)               |
| 4 | Dart の `cancel --batch B1 --alarm A1`                              | `removed`。C# 版の `list` は空になった                                          |
| 5 | 過去の時刻 (`2020-01-01 00:00`) で `add`                            | `0x80070057` (`CreateScheduledToastNotification` の時点)。手順 2 の C# 版と同じ |
| 6 | レジストリ登録 (`register-reg`) の後に即時の toast (`show`)         | 表示された (利用者の目視)                                                       |
| 7 | 手順 6 の直後に、約 90 秒後の toast を `add` (group `B2`、tag `A2`) | 指定時刻に表示された (利用者の目視)                                             |

- 手順 7 の `add` のプロセスは、予約の作成後すぐに終了している。toast は、そのプロセスが存在しない状態で表示された (W2 の予備的な所見。W2 としての合否はまだ判定しない)
- 時刻の扱いは手順 1 と同じ (オフセットなしは JST とみなす)

### 制約と気付き

- Dart FFI から `AddToSchedule()` を呼べた。手順 1 の C# 版と同じ操作 (`add`・`list`・`cancel`・`show`) が通った
- .NET の部分は不要だった。Dart 単独で WinRT の予約通知に届く
- 手書きのバインディングは、IID と vtable の位置を間違えても、コンパイルでは検出できない
  - 手順 3 (C# 版との照合) で、`IScheduledToastNotification2` の順序が正しいと確認できた。
    対象は `put_Tag`/`get_Tag`/`put_Group`/`get_Group` である
  - ほかのインターフェースの位置は、実際に呼べたことで確認した範囲にとどまる
- 本番で使う場合の保守の方法 (バインディングの生成、パッケージの採用) は未検討
- 参照の解放 (`Release`) は PoC では一部しか行っていない。長時間動くサーバーでは、リークの扱いを決める必要がある
- toast の表示には、手順 1 と同じく AUMID の登録 (HKCU のレジストリ) が要った。登録していない状態での Dart からの表示は、確かめていない (手順 2 で予約した toast は、表示の確認前に取り消した)

### 調査メモで未確認とされた事項

| 事項                                           | 実機の結果                                                                 |
| ---------------------------------------------- | -------------------------------------------------------------------------- |
| Dart の FFI から WinRT の予約通知 API に届くか | 届いた。`combase.dll` の直接呼び出しで、予約・一覧・取り消し・表示ができた |
| Dart から予約した toast が、指定時刻に出るか   | 出た (AUMID をレジストリに登録した状態)                                    |

### 設計への影響

- W0 手順 3 は合格。Core を Dart に統一する案は、Windows の予約通知については成立する
- Dart 単独で、手順 1 と同じ AUMID の登録方式 (HKCU のレジストリ) が使える。.NET の実行環境は要らない
- 手順 4 (Dart の HTTP サーバーへの統合、PoC-W6) に進める
- 未確認: パッケージ化 (MSIX) した Dart のプロセスからの呼び出し。`dart.exe` はパッケージ化されていないため、MSIX の AUMID を使う構成は別に確かめる必要がある
- 未確認: AOT コンパイルした exe からの呼び出し

### 後始末

- レジストリキー `HKCU\Software\Classes\AppUserModelId\Kallr.Poc.W01` は `unregister-reg` で削除済み
- 予約は、取り消しまたは発火により残っていない (`list` で確認済み)
